# Project workflow

- After each code change, run the checks appropriate to that change, then apply the update to the running local application. Confirm the old Reader process exits before starting the new one; launching StartReader.vbs while a healthy old service exists does not restart it.
- If FurinaTTS code or model configuration changed, restart and verify that service as well. Unrelated reader-only changes do not require unloading the model.
- Refresh the reader page after the backend restart so the frontend and backend use the same revision. Preserve the reading position and player settings. The user explicitly authorized reading, migrating state and refreshing their ParallelText reader tab for this and future project updates on 2026-11-08. Reuse that authorization without asking again; it does not extend to unrelated tabs or browser tasks.
- Check health, the served frontend, book metadata and relevant behavior after restart. Do not equate a successful launch command with an applied update. Reuse valid audio caches; invalidate only the affected audio when synthesis behavior changes.
- TTS is off by default at reader startup. Do not start FurinaTTS, its supervisor, repair generation or chapter preparation merely to apply a reader update. User-initiated playback may start synthesis and prefetch on demand; startup generation requires an explicit opt-in, not an inherited prepareChapter value.
